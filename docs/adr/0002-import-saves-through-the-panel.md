# An Import Saves Through the Panel, Not a Server Route

An import fills the form with the source language's eligible fields through the Panel's own content save, so they land as unsaved changes the editor can review or discard, behind Kirby's lock dialog and `update` permission check. We considered moving it to a server route and rejected every shape of one. Writing the `changes` version from PHP gives the editor nothing new and loses Kirby's lock dialog. Writing `latest` publishes without review and has to refuse whenever unsaved changes exist. Deleting the target language's content file, so Kirby falls back to the default language, also drops the translated title, slug, and every field outside the import, ignores another user's lock, and rests on a fallback Kirby marks for removal (`Content/Version.php`, checked against 6.0.0-beta.2).
